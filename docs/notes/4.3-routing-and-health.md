# 4.3 Routing and the /health endpoint

## What did I do in this step?

I added one new endpoint, `/health`, and a small function called `route()` that decides where each request goes.

Before this, every request went straight to `generateResponse`. Now every request first goes through `route()`.

---

## What is routing? (the simple version)

Think of a receptionist at a hospital.

- Someone walks in and says what they need.
- The receptionist looks at it and sends them to the right room.

`route()` is my receptionist:

- "Are you asking for `/health`?" -> I answer it myself, right here.
- "Anything else?" -> I send you to `generateResponse`, which handles `/echo`, `/files` and the rest, like before.

---

## What is /health?

It's a tiny endpoint that just says "I'm alive and working."

If you ask `GET /health`, the server replies:

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 15

{"status":"ok"}
```

That's it. It does no real work. No files, no database. It only proves the server is up and can answer.

---

## Why do I need it?

Because other tools keep asking "are you still alive?"

- **Cloud Run** (where I'll deploy) checks it to know if my app is healthy.
- **Docker** can use it to check the container.
- **My CI pipeline** (GitHub Actions) will wait for `/health` to say OK before it runs the tests.
- **Monitoring** (later) can watch it.

Without `/health`, they would have to guess if my server is okay.

It should always be fast and simple. If it did something slow, like reading a file, it could fail for a reason that has nothing to do with whether the server is alive.

---

## The code

```cpp
static std::string route(const std::string &method, const std::string &path,
                         const std::string &body, const std::string &dir,
                         const std::string &acceptEncoding) {
  if (path == "/health" && method == "GET") {
    const std::string json = "{\"status\":\"ok\"}";
    return "HTTP/1.1 200 OK\r\nContent-Type: application/json\r\n"
           "Content-Length: " +
           std::to_string(json.size()) + "\r\n\r\n" + json;
  }
  return HttpParser::generateResponse(method, path, body, dir, acceptEncoding);
}
```

And in `handleClient`, I swapped the call:

```cpp
// before
std::string response = HttpParser::generateResponse(method, path, body, filesDirectory, acceptEncoding);

// after
std::string response = route(method, path, body, filesDirectory, acceptEncoding);
```

### Line by line, in plain words

- `path == "/health" && method == "GET"`: only answer when it's exactly `/health` and it's a GET.
- `json`: the little message I send back.
- `"Content-Length: " + json.size()`: tells the client how many bytes the body is. The number must be right, or the client gets confused.
- `\r\n\r\n`: the blank line that separates the headers from the body in HTTP.
- `return HttpParser::generateResponse(...)`: if it's not `/health`, do what the server always did.

---

## Why is it `static`?

`static` on a function means "only this file can use it."

`route()` is used only inside `server.cpp`, so I keep it private. That way it can't clash with another function with the same name somewhere else in the project.

---

## Why only GET?

A health check just *asks* a question, it doesn't change anything, so GET is right.

If I do `POST /health`, it isn't handled by my `if`, so it falls to `generateResponse` and returns **404**. That's what I want.

---

## Why is this a good design?

Adding a new endpoint later is easy. I just add another `if` inside `route()`.

The next one will be `/metrics`, and it will go in the same place.

---

## How I tested it

```bash
cmake --build build
./build/http-server --directory /tmp/echoo-data &

curl -i localhost:4221/health            # expect 200 and {"status":"ok"}
curl -i -X POST localhost:4221/health    # expect 404 (only GET works)
curl -i localhost:4221/echo/hello        # expect 200 (old routes still work)

kill %1
```

All three gave the expected answers.

---

## Mistakes I should avoid

- Forgetting the blank line (`\r\n\r\n`) between headers and body.
- Putting the wrong number in `Content-Length`.
- Making `/health` slow or dependent on other things.
- Handling `/health` for every method instead of only GET.

---

## Quick summary

| Thing | What it does |
|---|---|
| `route()` | The receptionist: sends each request to the right place |
| `/health` | Says "I'm alive" with `{"status":"ok"}` |
| `static` | Keeps `route()` private to this file |
| GET only | Health checks only ask, they never change anything |
