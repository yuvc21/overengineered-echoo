# 4.3b Read PORT from the environment

> **Status:** done | **Area:** `src/main.cpp`, `src/server.hpp`, `src/server.cpp`

---

## What is happening

The server used to always listen on port **4221**, hardcoded. Now it checks an environment variable called `PORT` first. If it's there, it uses that. If not, it falls back to 4221.

## Why it matters

Cloud Run picks the port itself and tells your app through `PORT`. If the app ignores it and sits on 4221, Cloud Run can't reach it and the deploy fails.

Analogy: the mall says "your shop is number 8080". If you stand at number 4221 anyway, nobody finds you.

## Key terms

- **Environment variable:** a little note handed to the program when it starts, from outside the code. Same code, different note, different behaviour.
  ```bash
  PORT=8080 ./build/http-server --directory /tmp/data
  ```
- **`getenv("PORT")`:** reads that note. It gives text like `"8080"`, or `nullptr` if there's no note. Then `atoi` turns the text into a number.

## What was done

```cpp
// main.cpp
int port = 4221;
if (const char *env = std::getenv("PORT")) {
  int p = std::atoi(env);
  if (p > 0 && p < 65536) port = p;
}
Server server(directory, port);
```

```cpp
// server.cpp
Server::Server(const std::string &directory, int port)
    : server_fd(-1), filesDirectory(directory), port(port) {}
```

`Server` got a `port` member, and `setup()` now uses `htons(port)`. The startup message prints the real port too.

| `PORT` value | Port used |
|---|---|
| not set | 4221 |
| `8080` | 8080 |
| `abc`, `0`, `99999` | 4221 (not valid) |

## How to test

> [!NOTE]
> Run `pkill http-server` first. An old server still running holds the port and confuses everything.

```bash
cmake --build build

PORT=8080 ./build/http-server --directory /tmp/data &
ss -ltnp | grep http-server           # should show 8080
curl -i localhost:8080/health         # expect 200
pkill http-server

./build/http-server --directory /tmp/data &
curl -i localhost:4221/health         # expect 200 (default)
pkill http-server
```

- [x] `PORT=8080` listens on 8080
- [x] No `PORT` falls back to 4221
- [x] The startup message shows the real port

| Mistake | Symptom | Fix |
|---|---|---|
| Old server still on 4221 | `Failed to bind port 4221` | `pkill http-server` first |
| Didn't rebuild | still used 4221 | `cmake --build build` |
| Used `port` before adding the member | `'port' was not declared` | add `int port;` to the class and constructor |
| `filesDirectory(directory, port(port))` | `'port' cannot be used as a function` | each member gets its own brackets |
| Startup message said `4221` | looked like `PORT` was ignored, but it was only text | print `port`, and check with `ss -ltnp` |

</details>

## Remember

- The cloud tells your app its port through `PORT`, so don't hardcode it.
- Check the real port with `ss -ltnp`, not the log message.
- Kill old servers before every test.
